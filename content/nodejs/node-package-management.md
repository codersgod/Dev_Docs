# Package Management

## `package.json`: Dependencies + scripts
The `package.json` file is the required manifest configuration file located at the root of a project that contains essential project metadata (like name, version, and author), environment requirements, external libraries, and custom command shortcuts.

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "dependencies": { "express": "^4.18.0" },
  "devDependencies": { "jest": "~29.0.0" }
}
```
## `package-lock.json` – Locks exact dependency versions
A snapshot file automatically generated by npm that `tracks and locks down the exact version, origin URL, and security hash of every single package and sub-dependency installed`, ensuring identical builds across different machines.

## Semantic Versioning (semver)

Given `MAJOR.MINOR.PATCH`:

| Range | Meaning |
|---|---|
| `^4.18.0` | Accept minor + patch updates (`4.x.x`) |
| `~4.18.0` | Accept patch updates only (`4.18.x`) |
| `4.18.0` | Exact version, no updates |
| `*` | Any version (avoid in production) |

## Lockfiles

- `package-lock.json` (npm) - that tracks and locks down the exact version, origin URL, and security hash of every single package and sub-dependency installed, 
`yarn.lock`, `pnpm-lock.yaml`
- Commit lockfiles — they guarantee reproducible installs across machines.
- `npm ci` installs from the lockfile exactly, skipping the resolution step.
## `npx` – Run packages without install
Tells your system to download the tool temporarily instead of installing it permanently

## npm audit

```bash
npm audit          # list known vulnerabilities
npm audit fix      # auto-fix safe patches
npm audit fix --force  # force major-version bumps (review first)
```

## npm vs yarn vs pnpm

| | npm | yarn | pnpm |
|---|---|---|---|
| Speed | Moderate | Fast | Fastest |
| Disk usage | High | High | Low (hard links) |
| Workspaces | Yes | Yes | Yes |
| `node_modules` | Flat | Flat | Symlinked |
